- (direction) Headless express distillation selected because the supplied solution document is rich and pre-structured.
- (decision) The spec slug is website-crawling-structured-analysis, derived from the source topic rather than its document shape.
- (decision) The current contract targets the source-defined first-release MVP; explicitly second-stage functions remain non-goals for this spec.
- (decision) The system follows discover, select, extract, aggregate, classify, and generate stages so evidence and cost remain controllable.
- (capability) CAP-1: Accept and normalize a website URL, enforce domain eligibility, and discover candidate pages; success is a canonical target plus a mapped URL inventory with title and description metadata.
- (capability) CAP-2: Classify discovered pages and rank their business-information value; success is a deterministic page type and score for every candidate, with lightweight-model fallback only for unresolved URLs.
- (capability) CAP-3: Select a bounded, high-value sample and stop when required evidence is complete; success is five to ten pages when available, respecting type limits and the documented completeness gate.
- (capability) CAP-4: Retrieve readable content and provenance from the selected pages; success is Markdown, links, metadata, status, language, source URL, and scrape time for each successful page while failed pages remain visible.
- (capability) CAP-5: Clean and section-aware chunk scraped Markdown without losing semantic evidence; success is deduplicated chunks with site, page, section, index, and content-hash provenance.
- (capability) CAP-6: Extract page-local structured facts with explicit evidence; success is schema-valid facts that use empty values for uncertainty, distinguish facts from marketing claims, and attach quote and URL evidence to each core fact.
- (capability) CAP-7: Aggregate page facts into a normalized site-level fact set; success is synonym consolidation, conflict-aware evidence grouping, and reproducible confidence values that reflect page authority and source diversity.
- (capability) CAP-8: Choose primary and secondary categories from an approved taxonomy; success is a taxonomy-valid selection with reason, confidence, and evidence identifiers and no invented category.
- (capability) CAP-9: Generate the final structured website report only from aggregated facts; success is schema-valid names, categories, tags, descriptions, functions, users, sources, evidence, confidence, and crawl metadata with all content and length checks passing.
- (capability) CAP-10: Persist crawl, page, fact, and report state for audit and reanalysis; success is traceable records for sites, pages, facts, and versioned site reports linked through stable identifiers.
- (capability) CAP-11: Handle predictable provider and page failures without corrupting the analysis; success is bounded exponential retry for transient statuses, immediate surfacing of permanent errors, and accurate success and failure counts.
- (constraint) Integrate with the existing Python 3.12, FastAPI, PostgreSQL, and OpenAI Responses API codebase; Firecrawl v2 is the page discovery and retrieval provider.
- (constraint) Firecrawl handles discovery, rendering, and main-content extraction while the business system owns URL selection, page classification, fact aggregation, taxonomy matching, and quality control.
- (constraint) Do not merge a whole-site crawl into one model call; page-local extraction and site-level aggregation are mandatory boundaries.
- (constraint) The default MVP uses Map plus selected-page Scrape, caps the final sample at ten pages, and excludes low-value page classes according to crawl-policy.md.
- (constraint) Respect robots rules and never bypass login, CAPTCHA, access control, or other permission boundaries.
- (constraint) Page extraction may use only the current page, must return empty values when uncertain, and must preserve original evidence quotes and URLs.
- (constraint) Category generation is constrained to a maintained taxonomy rather than open-ended label invention.
- (constraint) The one-sentence Chinese description must be 10 to 50 characters and the detailed Chinese introduction must be 200 to 300 characters, fact-grounded, and free of unsupported superlatives.
- (constraint) Transient Firecrawl statuses 408, 429, 500, 502, 503, and 504 receive bounded exponential backoff; non-retryable failures surface without retry loops.
- (constraint) Persist original Markdown and content hashes so extraction can be rerun without unnecessary recrawling and evidence remains auditable.
- (decision) Adopt architecture-diagrams.md, crawl-policy.md, data-contracts.md, and quality-and-operations.md as spec-authored companions because the source contains load-bearing diagrams, matrices, schemas, and operational rules.
- (decision) The fully absorbed source remains an audit source rather than an adopted companion; downstream consumers use the kernel and companions as the complete contract.
- (assumption) Illustrative code snippets and numeric provider settings are treated as recommended initial defaults unless the source marks them as product requirements.
- (assumption) At least five useful pages is conditional on the site exposing that many eligible pages; the completeness gate can finish with fewer when all required evidence is already satisfied.
